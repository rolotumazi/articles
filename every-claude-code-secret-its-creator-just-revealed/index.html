Hooks: Rules That Fire on Events▶ 5:48

Next up are one of my favorite features of Claude Code, and the ones that I mainly teach in all the workshops we do at different companies, which are hooks. If you still don’t understand the concept of hooks, you can think of it as a series of rules that automatically fire based on an event. If you want it in layman’s terms, then imagine you have your phone. Let’s say you have an iPhone, and before you go to bed, it automatically goes into sleep mode or do not disturb. Technically, that’s a hook. That’s a hook based on a time. Let’s say 10:00 p.m. is your bedtime, or 11:30; then that would fire and execute your phone to not have notifications during that sleeping time. And then in the morning, when you wake up and it sees that you’re actually using your phone, you’re sending messages, it asks you, “Do you want me to remove this mode and go into the normal mode where we turn off your alarm and everything else is just normal?” Hooks work in exactly the same way.

So you can attach a hook to a session start, before any particular action or tool use, after a tool is used, after any or every edit, or even after a session ends. You have so many checkpoints where you can attach a hook. One example of a practical use case of a hook is this: most people rely on something like a Claude MD file to auto-inject all of their preferences. You can use it to say, “Always learn and understand our brand guidelines before we create any new asset.” But another way you can do this is to attach a hook. The way you can attach it is to say, “Set up a hook so that every time I start a new session in this project, you automatically read the brand guidelines.” So you’re forcing the tool calls of Claude Code to read this and have it in context each and every time.

And then you can also do the following, where you tag the Claude Code guide agent. This is my favorite thing to do from a syntax standpoint, because at the end of the day, a hook is just a series of code in what’s called a JSON file. It’s called a settings.json file. In case you don’t want to get your hands dirty, or you’re non-technical, then you can tag this specific agent and it will help you do it with the best syntax. You can see it writes this hook to your settings file directly. The next time you have a session start, it should be able to fire said hook and make sure that it auto-injects the same document every single time. The core difference between this versus relying on Claude Code with Claude MD is that this is deterministic. This will get shoved into that context window whether Claude Code wants it or not.

/branch: Side-Questing Without Risk▶ 13:39

Next up is a feature that I’ve also reviewed on this channel called /branch, and it comes in very handy when you have a little fork in the road where you want to decide, “Do I go path A or path B?” But you don’t want to risk path A in case that is the right path, and you feel like physically side-questing to investigate an additional idea or a different take. To put this into action, let’s say I have the following prompt, and I say something like, “I need your help to refine a proposal for a specific client, and these are the addresses of the files.” I break down what the situation is to give it context, I tell it exactly what I want the proposal to look like, for what denomination, and a series of criteria here on how it should rewrite it. So let’s assume it executed that. I ran this before this video just so that you wouldn’t have to watch me watch Claude Code crank it out. Let’s assume we get some version, and this goes through the current state of things.

But let’s say I want to experiment with really aggressive pricing, but I don’t want to flood that into my context window and have the language model start getting confused between our current rate versus this very aggressive different possible reality. So in order for us to side quest, we could do something like branch very aggressive pricing versions. Now we’re in a separate branch where I can ask for the exact same proposals with very different structures of pricing. The good part of this is, if I review this and it looks like this is the way to go, I can now purely go down this path and leave our old conversation in a way where, as you can see here, we can always resume it by entering claude -r with the session ID in any terminal.

Work Trees: Separate Desks for Separate Tasks▶ 16:07

Now this next tip is typically one that non-technical people run away from because it sounds very intimidating, but conceptually it’s actually unbelievably simple, which is using work trees and how to actually invoke them. Work trees — if the analogy of a tree isn’t helpful, you can think of it as having three separate desks with three separate agents with three separate types of work and documents. The goal is that each one can actually work mutually exclusively, without the risk that multiple agents are working on the exact same file, or trying to edit or write to the same file at the same time. So if we think of it as different lanes with different desks with different agents and different work, then lane one could be writing the client proposal, lane two could be website redesign, and lane three could be financial reporting, where all of these files shouldn’t have any form of overlap.

Now, it’s one thing to talk about it and another thing to show it. The syntax is the following. You would write claude — you don’t need this part, I’m just running this in YOLO mode — and then you’d do -w. This stands for work tree. This tells Claude that you are executing a separate desk with a separate set of work. In this case, we’re just basically assigning it what this work tree is about. So in this case, it’s about proposal for Acme company. Beyond that, there’s really not much to it. You just prompt as you normally would. So in this case, I would just say, “Write a revised proposal for Acme Corp based on their project notes in this folder. They’re now in phase two. Propose an upsell to enterprise tier for phase three.”

And again, exact same concept for another task. You’d enter the exact same syntax right here. You do the -w for a brand new desk, work tree, whatever concept makes sense, and now you have a separate lane called website update. This will be designated to adding testimonials to your website at the very bottom using real client names from our client folder. And then while this is running, you can also run this one, which is a board report that looks at X, Y, and Z, and then execute it. So if you’ve historically been intimidated by this concept, be intimidated no more. It’s really easy to execute and very useful.

/batch: Breadth Over Depth▶ 18:23

This next tip should be taken with a gigantic grain of salt and a lot of caution, especially if you’re very token conscious of your rate limits and everything that’s now happening with all these different usage capacities. If work trees can spin up three Claudes at once at different desks, technically batch can spin up five, 10, 15, 30 at once. So /batch has a higher emphasis on breadth of execution versus depth and thoughtfulness of how to derive the most of each singular agent.

The way it works is, if we pop into the terminal, you can open a session and do the following. Do /batch, then after batch, you have to enter some form of request. So you could say, “Update the hourly rate from 150 to 175 across all proposal files in the proposals folder, keep existing formatting, recalculate all line item totals, and the grand total in each proposal.” If we send this over, I will show you what happens. Now it enters plan mode, and in plan mode, it researches and sees basically what the scope of this task is. So now it’s going through each and every possible proposal that we have in our workspace. Once it finishes its plan, it goes through and breaks down all the context, all the formatting conventions that need to change, and what’s going to change in each and every proposal, so it has a draft of that. And then at the very bottom, it walks through the worker instructions template. Each worker that it will spin up receives the specific file, the exact old-to-new values for each line item, and the new grand total.

So now, if you go on to YOLO mode and execute it, it will employ as many agents as it wants, as if it’s venture capital funded and can hire whoever, whenever to execute the task. If you are rich in tokens, feel free to go for this. But if you are erring on the side of caution and you’re being frugal, I would avoid this for now.

–bare: Running Without the Bloat▶ 20:20

The next recommendation is one that I barely use, and I don’t really see many use cases, at least for myself, but just in case it’s useful for you: it’s basically adding what’s called --bare. And --bare will allow you to run a command without having Claude always inject the Claude MD, the skills, and all of the additional burden and bloat that comes into each and every session. When you add --bare, it will circumvent all of that and just execute the request you have in seconds. Just in case you thought I meant bear the animal, you would actually write it claude --bare and then execute some form of command.

One thing I noticed in trying to use this myself is that if you’re using your normal Max account or your subscription, then running this won’t work because it says “Not logged in.” So it appears — correct me if I’m wrong, if you know otherwise in the comments — that you have to use this via an API request, and then once you have the API, you should be able to run it. I tried multiple different ways to log in and exit my own terminal. But the core idea is you would send something like this. This is a shortcut that does work, that’s -p, and you ask the question and you get the answer immediately. But if you use this -p alone without the --bare, you’re not getting the benefits of not having any form of bloat or burden in the conversation. So you might have a use case on your end where this makes sense, but for myself, I’m okay with having the Claude MD loaded in for a basic question versus having to wrangle this myself.

Calling an Agent by Name at Session Start▶ 22:43

The last core tip was being able to call an agent by name at the very beginning of your Claude Code session. So instead of starting a Claude Code session and then asking Claude to go and remember how to use a specific agent, you start the session with the agent already injected in context. If that doesn’t make sense: you basically start a session with your agent already auto-injected with all the personalities, the quirks, the rules, the regulations, and the tools that it has access to.

If you watched my last video, I spoke at length about the power of this .claude folder and every permutation and everything inside that makes it tick.
